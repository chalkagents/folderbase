# v0.5.0-rc.1 Core release-candidate verification

Folderbase Core v0.5.0-rc.1 is the first installable release candidate for
the ordinary-folder protocol 0.5 architecture. The release keeps ordinary
workspace files authoritative while `.folderbase/` adds durable identity,
local versions, opaque-file capture, optional narrative adapters, template
guidance, sharing primitives, and crash-safe reorganization transactions.

This is an implementation prerelease, not a declaration that protocol 0.5 is
stable. The protocol 0.5 source distribution intentionally remains a sealed
candidate with `status: candidate` and
`distribution: repository-candidate-source-tree`. Released protocol 0.4
remains immutable.

## Public-tag installation proof

After publication, a fresh isolated install fetched the annotated public tag:

```text
Installing folderbase-cli v0.5.0-rc.1
  (https://github.com/chalkagents/folderbase.git?tag=v0.5.0-rc.1#45de7804)
folderbase 0.5.0-rc.1
```

The installed binary then exercised the ordinary-folder workflow outside the
source checkout:

1. `init --dry-run --json` produced an additive plan and a Core-owned SHA-256
   approval digest without writing.
2. A malformed approval value was rejected with
   `invalid_initialization_plan_digest` and no protocol write.
3. Applying the exact nested digest created only `.folderbase/` and
   `.folderbase/manifest.json`.
4. Shallow validation returned `valid: true` with no findings.

Install the exact reviewed commit for strict reproducibility:

```sh
cargo install \
  --git https://github.com/chalkagents/folderbase.git \
  --rev 45de7804bb4e57224e5b9495e4394441ce652f0b \
  --locked \
  folderbase-cli
```

The annotated public tag currently peels to that commit. Git tags can be moved
or deleted by repository administrators unless a separate protection policy
prevents it, so the commit-pinned command is the stronger reproducibility pin.
An isolated install using that exact `--rev` also fetched `#45de7804`, completed
successfully, and reported `folderbase 0.5.0-rc.1`.
