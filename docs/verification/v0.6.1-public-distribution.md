## Independent clean-install audit

The following commands were run from clean temporary roots against public
registries and release assets rather than this repository's build output:

```sh
npx --yes @folderbase/cli init . --json
npx --yes @folderbase/cli validate . --json
npx --yes @folderbase/cli --version
npx --yes @folderbase/cli protocol contract --json

cargo install folderbase-cli --version 0.6.1 --locked --root "$TEMP_ROOT"
"$TEMP_ROOT/bin/folderbase" --version
"$TEMP_ROOT/bin/folderbase" protocol contract --json

gh release download v0.6.1 \
  --repo chalkagents/folderbase \
  --pattern folderbase-v0.6.1-aarch64-apple-darwin \
  --pattern SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
```

The unpinned npm command resolved 0.6.1, created only `.folderbase/` and
`.folderbase/manifest.json` in an empty ordinary folder, and returned
`valid: true`. The crates.io installation compiled and installed 0.6.1 into
its isolated root. The downloaded Apple ARM binary matched `SHA256SUMS`.
Every executable reported `folderbase 0.6.1` and
`folderbase-compatibility-contract-v1` at contract version `1.0.0`.

The auditing Mac's direct `brew install` fetched the public 0.6.1 formula but
Homebrew refused installation because that machine's Xcode Command Line Tools
needed an OS-level update. This is not treated as release proof. The clean
macOS and Linux post-merge tap jobs above are the authoritative Homebrew
installation evidence.

## Deliberate nonclaims

This record proves public Core distribution and the stable compatibility
discovery surface. It does not claim that every optional capability is stable;
capabilities report their own maturity and query remains experimental. It also
does not claim App distribution, synchronization, hosted Cloud durability,
sharing, or Cloud Agent workspace execution.
