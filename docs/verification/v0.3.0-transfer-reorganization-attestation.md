# v0.3.0 transfer, reorganization, and attestation verification

Folderbase Core v0.3.0 establishes the public, local-first foundations needed
to move immutable Folderbase objects between devices and agents without
confusing a logical Folderbase with a particular directory instance.

This release does not apply or recover a reorganization plan, publish a Remote
Head contract, add cloud authorization or live sync, execute remote agents, or
issue a hosted sharing grant. Those remain later Core or Platform
responsibilities built on the public records and receipts in this release.

## Included public contracts

Since v0.2.1, Core now:

- defines and validates the canonical streaming manifest and digest model;
- streams immutable transfer sources without loading whole large files;
- creates deterministic, repeatable reorganization plans without silently
  mutating a working folder;
- receives and verifies canonical transfers into owned staging storage;
- installs a verified artifact atomically without clobbering an existing
  destination and returns an integrity receipt;
- attests one exact logical Folderbase root and one physical root instance;
  and
- exposes stable CLI receipts for root attestation.

The canonical model covers regular files of every type as opaque byte streams
plus chunk and integrity metadata. Large media and immutable database-file
captures use the same bounded streaming contract. Calling a database capture
an application-consistent snapshot requires a format-aware adapter and is
outside this release, as are semantic parsing and installation into canonical
Folderbase history.

## RED evidence

Before the release edit, the release assertion:

```sh
cargo metadata --no-deps --format-version 1 | jq -e \
  '([.packages[] |
      select(.name == "folderbase-core" or .name == "folderbase-cli") |
      .version] |
     length == 2 and all(.[]; . == "0.3.0")) and
   ([.packages[] |
      select(.name == "folderbase-cli") |
      .dependencies[] |
      select(.name == "folderbase-core") |
      .req] == ["^0.3.0"])'
```

returned `false`: both public crates were still v0.2.1 and the CLI still
required Core `^0.2.1`.

The feature-level RED/GREEN evidence is retained in PRs #13 through #19. ADRs
0001 and 0003 are accepted; ADR 0002 remains proposed because apply/recovery is
deliberately outside this release.

## GREEN evidence

The release candidate must satisfy:

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps --locked
cargo test --workspace --all-features --locked
node scripts/verify-reorganization-digest-vector.mjs
scripts/check-ci-policy.sh
scripts/check-public-eclipse.sh
scripts/test-package-install.sh
folderbase 0.3.0
Extracted Cargo packages are self-contained and testable.
```

The hosted release-candidate run must additionally pass the public receiver,
root-attestation, and CLI contracts on macOS and Windows.
