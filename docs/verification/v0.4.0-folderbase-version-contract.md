# v0.4.0 Folderbase Version contract verification

Folderbase Core v0.4.0 releases `folderbase-version-v1`: a bounded, portable
full-state artifact with an independently specified canonical digest, a closed
public schema, positive and negative conformance vectors, and a Rust runtime
implementation.

The repository/tag source archive is the normative cross-language distribution.
The `folderbase-core` and `folderbase-cli` Cargo packages are the runtime and CLI
packages; they intentionally do not claim to contain the workspace-level schema,
corpus, or independent reference encoder.

## Exact transition base

The release transition starts from accepted contract merge
`de760987af058740e2d997923f71a56eb01140d2`, after its post-main CI passed.

## RED evidence

Before the release edit:

- the Cargo metadata assertion for Core and CLI v0.4.0 plus the CLI's Core
  `^0.4.0` dependency returned `false`;
- `protocol/releases/0.4/folderbase-version-v1.json` did not exist;
- `protocol/releases/0.4/folderbase-version-v1.candidate.json` still existed with
  `status: candidate`; and
- ADR-0004 was still Proposed.

These failures establish the release-state seam independently of the already
green feature contract.

The first online package-verifier attempt stopped on a crates.io low-speed
timeout while fetching the `iana-time-zone-haiku` index entry. An offline retry
created the same 48-file and 10-file packages but exhausted the local disk while
compiling. After removing only disposable build output and disabling debug and
incremental build artifacts, the unchanged verifier and packaged inputs passed
offline end to end. These were local network and storage conditions, not
contract or package failures.

This evidence observes the GitHub source tag and GitHub release only. It does
not claim crates.io publication, Cloud authorization, live sync, or a
hosted-byte guarantee.
